# LiveType Remote — تطبيق الأندرويد

تطبيق Android أصلي (Kotlin + Jetpack Compose + Material 3) يعمل كنظير لتطبيق الويندوز **LiveType Bridge**: تكتب أو تملي صوتيًا على الهاتف (بأي لوحة مفاتيح، وخاصة Gboard)، فيظهر النص لحظيًا في الخانة النشطة على اللابتوب — عبر الشبكة المحلية فقط.

> لا يوجد تحويل صوت→نص داخل التطبيق. الإملاء الصوتي مسؤولية Gboard/لوحة النظام، والتطبيق يرسل النص الناتج فقط.

## طريقة عمله في 3 خطوات
1. شغّل **LiveType Bridge** على اللابتوب واضغط «ربط هاتف» — يظهر QR و PIN.
2. افتح هذا التطبيق → «ربط اللابتوب» → امسح الرمز (أو أدخل البيانات يدويًا).
3. اكتب/املِ في الخانة — كل تغيير يُرسل فورًا كعمليات دقيقة (`deleteCount` + `insertText` + `revision`).

## البنية
```
app/src/main/java/com/livetype/remote/
  core/
    protocol/    # عقد الاتصال (نفس JSON camelCase المستخدم في تطبيق ويندوز)
    textdiff/    # حساب الفرق بين النصوص (backspaces + insert)
    session/     # منطق البث: revisions، reset_stream، إعادة المزامنة
    network/     # OkHttp WebSocket + heartbeat + إعادة اتصال تلقائية
    pairing/     # تحليل QR + تخزين مشفر (EncryptedSharedPreferences)
  ui/            # Compose + Material 3، عربي RTL + إنجليزي + وضع داكن
app/src/test/    # اختبارات JVM: التوافق مع البروتوكول، TextDiff، ترتيب revisions
```

## بناء الـ APK

### عبر GitHub Actions — تلقائي بالكامل
لا تحتاج إلى تشغيل أي شيء يدويًا. **كل دفع (push) إلى `main` ينشر إصدارًا جديدًا تلقائيًا** بلا خطوات إضافية:

1. `plan` — يحدد هل هذا الالتزام يحتاج إصدارًا، ويحسب رقم الإصدار التالي.
2. `verify` — يشغّل اختبارات الوحدة ويبني APK التجريبي (يعمل أيضًا على طلبات الدمج وبقية الفروع، بلا إصدار).
3. `signed_release` — يبني APK وAAB موقّعين ويتحقق من التوقيع ويحسب SHA-256 (بيئة `android-release`).
4. `publish_release` — ينشئ GitHub Release ويؤكد اكتمال الملفات.

**قواعد الإصدار:**
- رقم الإصدار يزيد تلقائيًا: أعلى وسم مستقر + 1 في قيمة patch، أي `v1.0.3` ⇒ `v1.0.4`.
- لرفع minor أو major أضف وسمًا صريحًا في رسالة الالتزام المدفوع: `[release:minor]` أو `[release:major]` (الافتراضي patch دائمًا).
- `versionCode` مشتق من رقم الإصدار نفسه: `major×1,000,000 + minor×1,000 + patch` (مثال `1.0.4` ⇒ `1000004`). لذلك هو تصاعدي دائمًا ولا يعتمد على عدّاد التشغيلات.
- إعادة تشغيل نفس الالتزام لا تُنشئ إصدارًا مكررًا: إذا كان الالتزام موسومًا مسبقًا يُتخطّى الإصدار بأمان.
- طلبات الدمج وبقية الفروع: اختبارات وبناء تجريبي فقط، بلا إصدار وبلا استخدام لمفاتيح التوقيع.

**ملفات الإصدار:** `AirType-vX.Y.Z.apk` (تثبيت مباشر)، `AirType-vX.Y.Z.aab` (Google Play)، `SHA256SUMS`، `BUILD-INFO.txt` (فيه versionName/versionCode/الالتزام/سبب التشغيل).

مفاتيح التوقيع لا تُحفظ في الشيفرة أو ملفات المستودع. تُقرأ فقط من أسرار GitHub المشفّرة داخل بيئة `android-release`: `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. البيئة مقيّدة بفرع `main`.

> `Run workflow` اليدوي ما زال متاحًا كأداة إعادة محاولة فقط؛ لن يُصدر نسخة جديدة إن كان الالتزام قد نُشر بالفعل.

### بناء محلي (اختياري)
يتطلب JDK 17 + Gradle 8.9 + Android SDK (compileSdk 35):
```
gradle --no-daemon :app:testDebugUnitTest
gradle --no-daemon :app:assembleDebug
# الناتج: app/build/outputs/apk/debug/app-debug.apk
```

بناء نسخة release محليًا يتطلب مفتاح التوقيع في متغيرات البيئة **وأيضًا** تمرير رقم الإصدار صراحةً،
وإلا يفشل البناء برسالة واضحة بدل أن يُنتج نسخة برقم إصدار افتراضي:
```
gradle --no-daemon :app:assembleRelease :app:bundleRelease \
  -PappVersionName=1.0.4 -PappVersionCode=1000004
```

## الاقتران مع برنامج الويندوز
- تأكد أن الهاتف واللابتوب على **نفس شبكة Wi-Fi** (أو نقطة اتصال الهاتف نفسها).
- عند أول اقتران من اللابتوب سيطلب ويندوز السماح عبر جدار الحماية — اختر «السماح» للشبكات الخاصة.
- رمز الـ QR يحتوي: العنوان + المنفذ + معرّف الجلسة + الـ PIN المؤقت (بدون token).
- بعد نجاح أول PIN يحفظ الهاتف `clientId + token` الدائم. في التشغيلات التالية ينتظر Beacon الحالي ثم يعيد الاتصال دون PIN، حتى بعد إعادة تشغيل الديسكتوب.
- الانقطاع المؤقت يعيد فقط revisions غير المؤكدة؛ الديسكتوب يحتفظ بمرآة الجلسة ويرفض أي replay مطبق، لمنع تكرار النص.
- إعادة المزامنة بعد إعادة الاتصال تتم على خطوتين: يطلب الهاتف `reset_stream` أولًا، ثم يكتب النص كاملًا بعد أن يخبره الردّ (`ack`) بطول ما في خانة الكمبيوتر فعلًا. لأن إرسال الكتابة كاملة مع الطلب كان يكرّر النص إذا ضاع `ack` واحد.

## الخصوصية والصلاحيات
- `INTERNET` و `ACCESS_NETWORK_STATE` للاتصال المحلي فقط — لا خوادم ولا تتبع.
- `CAMERA` لمسح رمز QR فقط (ML Kit bundled — لا يُنزّل أي شيء وقت الاستخدام).
- `RECORD_AUDIO` للإملاء الصوتي الاختياري فقط: الصوت يمرّ إلى خدمة التعرّف على الكلام في النظام، ولا يُرسل إلى أي خادم تابع لنا ولا يُحفظ. من لا يستخدم الإملاء لا يُطلب منه الإذن.
- بيانات الاقتران (إن اخترت «تذكّر») محفوظة مشفرة عبر EncryptedSharedPreferences.
- لا يُطلب الموقع ولا الملفات. الميكروفون مذكور أعلاه، ولا يُطلب إلا عند بدء الإملاء.
- الاكتشاف بين الهاتف واللابتوب عبر **UDP فقط** (منفذ 53018)؛ لا يوجد mDNS في أي من الطرفين ولا حاجة إلى `NsdManager`.

## بروتوكول الرسائل (نفس عقد تطبيق ويندوز)
| رسالة | الاتجاه | حقول أساسية |
|---|---|---|
| `pair_request` | هاتف→كمبيوتر | أول مرة: sessionId, pin, deviceName, clientId — لاحقًا: sessionId, clientId, token — وفي الحالتين: protocolVersion |
| `session_ready` | كمبيوتر→هاتف | ok, token, heartbeatIntervalMs, protocolVersion |
| `text_edit` | هاتف→كمبيوتر | token, revision, deleteCount, insertText, timestamp |
| `ack` | كمبيوتر→هاتف | revision, applied, reason |
| `reset_stream` | بالاتجاهين | baselineRevision, appliedLength |
| `heartbeat` / `heartbeat_ack` | بالاتجاهين | timestamp, lastRttMs |
| `disconnect` / `error` | بالاتجاهين | reason / errorCode |

كل الحقول camelCase مثلما ينتجها `System.Text.Json` في تطبيق الويندوز، واختبار `ProtocolCompatTest` يثبّت هذا الشكل.

### تفاوض إصدار البروتوكول
- الإصدار الحالي للبروتوكول هو **1**، معرّف في `Envelope.ProtocolVersion.CURRENT`.
- رمز QR يحمل الحقل `v`. غيابه يعني الإصدار 1، وإن كان أعلى من إصدار التطبيق يرفضه التطبيق برسالة واضحة تطلب التحديث (`UNSUPPORTED_VERSION`) بدل محاولة اتصال بعقد غير مفهوم.
- طلب الاقتران يرسل `protocolVersion`، ويرد الويندوز بالحقل نفسه في `session_ready`. الطرف الذي لا يجد الحقل يعتبره 1.
- إن أرسل هاتف إصدارًا أعلى من إصدار الويندوز يرد الأخير بخطأ `unsupported_version` ويعامله الهاتف كخطأ نهائي فلا يعيد المحاولة تلقائيًا.
- كل التغييرات في هذا العقد إضافية: هاتف قديم مع ويندوز جديد، وويندوز قديم مع هاتف جديد، يعملان كما هما.
